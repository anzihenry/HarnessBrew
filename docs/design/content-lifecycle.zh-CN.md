# 内容库存、回收与精确修复

## 契约

内容以摘要为主键，库存保留文件清单及精确来源（坐标、commit、快照）。活动资产引用库存；引用集合从活动安装记录推导，不保存独立计数。升级后的旧摘要保留库存记录。内容是否可回收由当前活动引用决定。

cleanup 只处理登记在库存且没有活动引用的摘要。预览记录当前目录身份及内容，执行前再次核验。缺失目录可移除库存；修改过的内容及未登记目录保留并报告。来源缓存、历史 revision 和用户保留的隔离副本不属于 cleanup 范围。

repair 使用已安装摘要和 commit，不升级或重新求解依赖。缺失内容自动恢复；修改内容必须指定 `--restore-content`，先隔离原目录，修复提交后保留副本。`--overwrite-owned` 仍仅控制共享目标键和区块。来源必须仍被信任，恢复内容必须与库存清单和摘要一致；缓存不可用时尝试获取精确 commit，不能退回最新版本。

恢复内容在写事务前准备；事务内重新校验 revision、信任、内容和目标前置条件。隔离、发布、目标修复和状态提交共用日志。提交前失败恢复原目录；提交后保留正确内容及隔离证据。无法证明归属的外部变化导致恢复冲突。

Home 格式增加必需的内容库存；不从缺失字段或磁盘未知目录自动推断所有权。按现有不兼容策略，缺少库存的旧 Home 被拒绝，须使用新 Home。测试夹具与发布文档同步更新。

## 分任务交付

1. 契约与验收场景（本文）。
2. 内容库存、引用不变量、安装及升级登记。
3. 按摘要回收计划、缺失目录处理、执行时核验。
4. 精确恢复内容准备与来源失败处理。
5. 内容隔离/发布事务、回滚及共享引用修复。
6. Doctor、CLI/SDK 结果与文档。
7. 生命周期、并发、崩溃和跨平台候选包验收。

## 多摘要与局部修复

`repair <asset>` 只验证并修复指定资产；恢复共享内容时自动扩展到引用同一摘要的所有资产。未选资产的版本、引用和操作记录保持不变，其内容或目标损坏不会阻止本次修复。局部修复成功不代表整个 Home 健康，使用 `doctor` 获取完整检查结果。

`repair --all`（SDK：`{ kind: "repair", all: true }`）修复所有活动资产，按摘要去重准备恢复内容，在同一事务中发布。任一摘要无法验证或修改内容未获 `--restore-content` 授权，均不发布；执行失败时整体回滚。`--all` 不能与资产参数或 placement 选择一起使用。预览仍通过 `--dry-run`，应用仍验证预览时的状态与内容证据。
